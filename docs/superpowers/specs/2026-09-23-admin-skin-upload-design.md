# 양치왕 관리자 AR 스킨 업로드 설계

- 작성일: 2026-09-23
- 범위: 관리자 비밀번호 로그인, Drive 스킨 업로드, AR 보정 미리보기, 활성화, 학생 스킨 목록 제공
- 관련 설계: `docs/superpowers/specs/2026-09-23-brush-king-ar-challenge-design.md`

## 1. 목적

관리자 한 명이 앱을 재배포하지 않고 투명 배경 PNG/WebP AR 스킨을 계속 추가한다. 업로드한 이미지는 얼굴 미리보기에서 위치·크기·회전을 보정한 뒤에만 활성화한다. 학생은 활성 스킨만 선택하고, 기본 스킨은 Drive 장애에도 계속 사용한다.

## 2. 범위

### 포함

- `/admin` 비밀번호 로그인과 4시간 관리자 세션
- PNG/WebP 스킨 업로드와 Drive 전용 폴더 저장
- 스킨 이름, AR 보정값, 정렬 순서, 활성 상태 저장
- 기준 얼굴 이미지 위의 실시간 보정 미리보기
- 스킨 목록, 수정, 활성화/비활성화
- `challenge.get`을 통한 활성 스킨 목록 제공
- 학생 스킨 선택기와 AR 렌더러의 동적 스킨 지원

### 제외

- 보상 일수와 스킨 연결
- 학생별 스킨 획득·착용 컬렉션
- 왕관 영구 지급
- 완주 소감

제외 항목은 다음 Phase 4 하위 프로젝트에서 서버 권위 보상으로 구현한다.

## 3. 관리자 사용자 흐름

1. 관리자가 `/admin`에서 비밀번호를 입력한다.
2. 로그인 성공 후 `스킨 관리`를 연다.
3. `새 스킨 추가`에서 PNG/WebP 파일과 이름을 선택한다.
4. 브라우저가 형식, 2MB 용량, 이미지 디코딩을 먼저 검증한다.
5. 기준 얼굴 위에 스킨을 겹쳐 보고 좌우·상하·크기·회전 슬라이더를 조절한다.
6. `비활성 저장` 또는 `저장하고 활성화`를 선택한다.
7. 목록에서 기존 스킨을 수정하거나 비활성화한다.

삭제는 제공하지 않는다. 기존 학생 기록과 미래의 보상 참조를 보존하기 위해 비활성화만 허용한다.

## 4. 구조와 데이터 흐름

### Next.js

- `/admin/login`: 비밀번호 로그인
- `/admin/skins`: 스킨 목록과 활성 전환
- `/admin/skins/new`: 파일 선택, 미리보기, 보정, 저장
- 관리자 API 어댑터는 토큰 첨부와 세션 만료 처리를 숨긴다.
- 업로드 중 세션이 만료되면 선택한 파일을 제외한 이름과 보정값을 `sessionStorage`에 임시 보존한다. 브라우저 보안상 파일은 다시 선택해야 한다.

### Apps Script

- `admin.login`: 비밀번호 검증과 관리자 세션 발급
- `admin.session.get`: 관리자 세션 확인
- `admin.asset.upload`: 파일 검증, Drive 저장, 자산 메타데이터 저장
- `admin.skin.save`: AR 보정값과 활성 상태 저장
- `admin.skin.list`: 활성·비활성 스킨 전체 조회
- `admin.skin.setEnabled`: 스킨 활성 전환

업로드는 JSON 본문의 Base64 파일로 전송한다. 파일의 원본 바이트 크기를 2MB로 제한하고, Apps Script와 브라우저 양쪽에서 MIME과 확장자를 다시 검증한다.

### Google Drive와 Sheets

- Drive 전용 폴더에 원본 이미지를 저장한다.
- 스킨은 학생에게 보여주는 일반 그래픽이므로 링크 열람 권한을 설정한다.
- `Assets` 시트: `assetId`, `assetType`, `name`, `driveFileId`, `publicUrl`, `mimeType`, `byteSize`, `version`, `createdAt`
- `Skins` 시트: `skinId`, `assetId`, `anchorX`, `anchorY`, `scale`, `rotationOffset`, `enabled`, `sortOrder`, `updatedAt`
- 이미지는 Drive에만 보관하고 Sheets에 Base64를 저장하지 않는다.

## 5. 인증과 보안

- 학교 Google 계정 로그인은 사용하지 않는다.
- 관리자 비밀번호는 Script Properties의 솔트·해시로만 유지한다.
- 세션 토큰은 충분히 긴 난수로 발급하고, 서버는 토큰 해시만 CacheService에 4시간 보관한다.
- 세션 토큰은 인증 헤더 대신 기존 `text/plain` JSON 요청의 `auth.adminToken`으로 보낸다.
- 비밀번호·세션 토큰·업로드 Base64를 로그에 남기지 않는다.
- 서버는 PNG/WebP 파일 시그니처와 MIME를 함께 검증한다.
- SVG, HTML, 애니메이션 형식은 허용하지 않는다.
- 로그인 실패 횟수를 짧은 시간 단위로 제한한다.

## 6. AR 보정 모델

관리자 스킨은 기존 얼굴 추적 결과에 다음 값을 적용한다.

- `anchorX`: 얼굴 중심 대비 좌우 이동량
- `anchorY`: 얼굴 중심 대비 상하 이동량
- `scale`: 얼굴 너비 대비 스킨 너비 배율
- `rotationOffset`: 얼굴 기울기에 더하는 보정 각도

값은 서버에서도 안전 범위로 제한한다. 관리자 미리보기와 학생 AR 렌더러는 같은 좌표 계산 함수를 공유해 결과가 달라지지 않게 한다.

## 7. 오류 처리와 복구

- 클라이언트 검증을 통과해도 서버에서 모든 파일과 보정값을 다시 검증한다.
- Drive 파일 생성 후 Sheets 저장이 실패하면 새 파일을 휴지통으로 이동한다.
- 세션 만료는 전용 오류 코드로 응답해 로그인 화면으로 보낸다.
- 재로그인 후 이름과 보정값을 복구하되 파일은 다시 선택하게 한다.
- Drive 이미지가 로드되지 않으면 해당 스킨을 선택 목록에서 숨기고 기본 스킨을 계속 제공한다.
- 관리자가 저장 버튼을 연속으로 누르면 첫 요청이 완료될 때까지 버튼을 잠긴다.

## 8. 학생 앱 연동

`challenge.get`의 `skins` 배열은 활성화되고 유효한 스킨만 반환한다. 각 항목은 `skinId`, `name`, `imageUrl`, `anchorX`, `anchorY`, `scale`, `rotationOffset`, `version`, `sortOrder`를 포함한다.

기본 고양이·토끼·곰 스킨은 정적 자산으로 유지한다. 서버 스킨은 기본 스킨 뒤에 `sortOrder`로 정렬한다. 서버 목록이 없거나 이미지 로드에 실패해도 기본 세 개의 사용성은 보장한다.

## 9. 테스트 전략

- 단위 테스트: 비밀번호 해시, 토큰 만료, 로그인 실패 제한, 파일 시그니처, MIME, 2MB 경계, 보정값 범위
- API 테스트: 미인증 요청, 만료 세션, Drive 성공/Sheets 실패 복구, 활성 목록
- 컴포넌트 테스트: 로그인, 파일 거부, 미리보기 슬라이더, 중복 저장 방지, 활성 전환
- 브라우저 테스트: 관리자 로그인부터 업로드·보정·활성화, 학생 스킨 노출까지 390px 모바일과 데스크톱에서 검증
- 개인정보 테스트: 비밀번호·세션 토큰·Base64가 로그, Sheets, 테스트 스냅샷에 남지 않음을 확인

## 10. 완료 기준

- 관리자가 Google 로그인 없이 비밀번호로 접속한다.
- 유효한 PNG/WebP를 업로드하고 미리보기에서 보정한다.
- 비활성 저장과 활성 저장을 구분한다.
- 활성화한 스킨이 재배포 없이 학생 선택 화면과 AR 화면에 나타난다.
- 잘못된 파일, 세션 만료, Drive/Sheets 일부 실패에서 복구 가능한 안내를 제공한다.
- 기존 기본 스킨과 양치 흐름에 회귀가 없다.
