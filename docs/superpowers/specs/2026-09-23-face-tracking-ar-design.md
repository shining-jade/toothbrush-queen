# 얼굴 추적 AR 스킨 설계

- 작성일: 2026-09-23
- 상위 설계: `docs/superpowers/specs/2026-09-23-brush-king-ar-challenge-design.md`
- 범위: Phase 3의 얼굴 추적, 기본 AR 스킨, 마지막 날 왕관, 얼굴 감지시간

## 1. 목적과 성공 기준

학생이 스마트폰 전면 카메라를 보며 양치할 때 귀여운 2D 소품이 얼굴 움직임을 따라가도록 한다. 이 기능은 양치 정확도나 학생 신원을 판단하지 않으며, 참여 경험을 즐겁게 만드는 용도다.

성공 기준은 다음과 같다.

1. 학생은 1분, 3분, 자유 양치 중 하나를 선택하고 기본 AR 스킨 3종 중 하나를 직접 고른다.
2. 1분은 60초, 3분은 180초에서 시작해 1초씩 0초까지 감소한다. 자유 양치는 0초부터 실제 진행시간을 증가시킨다.
3. 고양이, 토끼, 곰돌이 스킨은 얼굴 위치·크기·기울기를 자연스럽게 따라간다.
4. 이미 `목표 일수 - 1`개의 스탬프를 가진 학생은 기본 스킨 대신 양치왕 왕관을 자동 착용한다.
5. 얼굴이 보이지 않아도 타이머는 계속되며 안내 문구만 표시한다.
6. 얼굴 감지시간은 브라우저 메모리에서만 누적해 완료 요청에 초 단위 숫자로 전송한다.
7. 영상, 사진, 캡처, 랜드마크 좌표는 저장하거나 서버로 전송하지 않는다.
8. 카메라 또는 추적기 실패가 챌린지 참여를 막지 않는다.

## 2. 학생 흐름

1. 학생이 학생 홈에서 오늘의 양치 도전을 연다.
2. 앱이 학생 토큰으로 `progress.get`을 호출해 현재 스탬프 수와 목표 일수를 확인한다.
3. 학생이 1분, 3분 또는 자유 양치를 선택한다.
4. 마지막 도전일이 아니면 고양이, 토끼, 곰돌이 스킨 카드 중 하나를 고른다.
5. 마지막 도전일이면 스킨 선택을 생략하고 “마지막 도전! 양치왕 왕관이 자동으로 적용돼요.”를 표시한다.
6. 카메라 미저장 안내를 확인한 뒤 전면 카메라 권한을 요청한다.
7. `brushing.start` 성공 후 카메라, 타이머, 얼굴 추적을 함께 시작한다.
8. 고정 타이머는 60 또는 180에서 0까지 감소한다. 자유 양치는 `00:00`부터 증가하고 60초가 지나면 직접 완료할 수 있으며 300초에서 자동으로 준비 완료 상태가 된다. 브라우저가 숨겨진 시간은 모든 모드의 진행시간에서 제외한다.
9. 얼굴이 감지되지 않으면 “얼굴이 화면에 보이도록 해주세요!”를 표시하되 타이머는 멈추지 않는다.
10. 고정 타이머가 0초가 되거나 자유 양치가 최소 60초를 채우면 완료 버튼을 활성화한다. 제출 시 추적기와 카메라를 종료한다.

진행률 조회가 실패하면 재시도 안내를 표시한다. 카메라 또는 MediaPipe만 실패한 경우에는 기존 타이머 전용 모드로 이어 간다.

## 3. 스킨 구성

초기 정적 에셋은 투명 배경 PNG 또는 WebP 네 개로 제공한다.

| ID | 표시 이름 | 구성 | 적용 규칙 |
|---|---|---|---|
| `cat` | 냥냥 볼터치 | 고양이 귀와 볼터치 | 기본 선택 |
| `rabbit` | 반짝 토끼 | 토끼 귀와 작은 반짝이 | 기본 선택 |
| `bear` | 하트 곰돌이 | 곰 귀와 작은 하트 | 기본 선택 |
| `crown` | 양치왕 왕관 | 왕관과 축하 반짝이 | `acceptedDays === targetDays - 1`일 때 자동 적용 |

각 스킨은 얼굴 위쪽 소품과 얼굴 주변 장식을 하나의 투명 이미지로 만든다. 글자와 로고는 넣지 않는다. 스킨 레지스트리는 에셋 경로, 접근성 이름, 기준 폭, 세로 오프셋, 회전 보정값을 가진다. 이후 관리자 업로드 스킨도 같은 렌더링 인터페이스를 사용한다.

## 4. 얼굴 추적 구조

`@mediapipe/tasks-vision`의 Face Landmarker를 클라이언트에서 동적 로딩한다. WASM과 얼굴 랜드마커 모델은 앱의 `public` 아래에 버전을 고정해 포함하고, 실행 중 외부 CDN이나 모델 서버에 의존하지 않는다.

추적기는 `requestAnimationFrame` 루프에서 동작하되 실제 추론은 최대 15fps로 제한한다. 한 명의 얼굴만 처리하며 blendshape 출력은 끈다. 얼굴 좌표 배열은 현재 프레임의 자세 계산이 끝나면 참조를 폐기한다.

눈 바깥점과 이마·양쪽 얼굴 가장자리 기준점을 사용해 다음 화면 좌표를 계산한다.

- 중심: 양쪽 얼굴 가장자리의 중간점
- 너비: 양쪽 얼굴 가장자리 사이 거리 × 스킨별 배율
- 높이 위치: 이마 기준점 + 스킨별 세로 오프셋
- 회전: 양쪽 눈을 잇는 선의 각도

전면 카메라 미리보기는 좌우 반전되므로 x 좌표와 회전 방향을 화면 기준으로 변환한다. 위치, 크기, 회전은 지수 이동평균으로 보간해 작은 떨림을 줄인다. 스킨은 카메라 위의 절대 배치 이미지 레이어로 렌더링하며 버튼과 안내 문구보다 낮은 z-index를 사용한다.

MediaPipe의 영상 추론은 동기식으로 메인 스레드를 막을 수 있으므로 초기 버전은 15fps 제한과 프레임 중복 방지로 부하를 제어한다. 저사양 기기에서 측정한 뒤 별도 Web Worker는 후속 최적화로 남긴다.

## 5. 모듈 경계

- `lib/face-tracking`: MediaPipe 로딩, 영상 프레임 추론, 정리 책임
- `features/ar-skins/skin-registry`: 스킨 메타데이터와 마지막 날 선택 규칙
- `features/ar-skins/face-pose`: 랜드마크에서 렌더링용 위치·크기·회전을 만드는 순수 함수
- `features/ar-skins/ar-camera-preview`: video, 스킨 오버레이, 감지 상태 메시지, 감지시간 연결
- `features/brushing-session`: 시간·스킨 선택 단계, 카메라·타이머 수명주기, 완료 데이터 연결

브라우저용 추적기는 인터페이스 뒤에 두어 컴포넌트 테스트에서 결정적인 가짜 결과를 주입한다. MediaPipe 결과 타입이 화면 컴포넌트나 Apps Script 계약으로 새어 나오지 않게 한다.

## 6. 얼굴 감지시간

추적 결과에 얼굴이 하나 이상 있을 때만 감지 상태를 참으로 본다. 연속 프레임 사이의 시간을 `performance.now()`로 누적하되, 긴 멈춤이나 백그라운드 전환이 한 번에 더해지지 않도록 한 구간의 최대 누적값을 제한한다. 페이지가 숨겨졌을 때는 누적하지 않는다.

완료 시 밀리초를 초 단위 소수로 변환하고 전체 실제 진행시간을 넘지 않도록 제한한다. 카메라나 추적기를 사용할 수 없으면 `faceDetectedSec`는 `null`이다. 좌표, 감지 이력, 얼굴 특징값은 요청에 포함하지 않는다.

## 7. 고정 시간과 자유 양치

시간 선택 값은 `60`, `180`, `free` 세 가지다. 고정 모드는 남은 시간을 `분:초`로 표시하면서 감소하고, 자유 양치는 경과 시간을 `분:초`로 표시하면서 증가한다.

자유 양치는 너무 짧은 참여가 바로 스탬프로 인정되지 않도록 60초 이전에는 완료 버튼을 비활성화한다. 60초 이후에는 학생이 직접 완료할 수 있고, 카메라가 장시간 켜진 채 방치되지 않도록 300초에서 자동으로 준비 완료 상태가 된다. 완료 화면은 모든 모드에서 “총 N분 N초 동안 양치했어요”를 표시한다.

시작 계약은 선택 값을 그대로 서명된 시도 토큰에 포함한다. 서버는 고정 모드에서 선택한 시간이 실제로 지났는지 검증하고, 자유 모드에서는 60~300초 범위인지 검증한다. 완료 요청의 `elapsedSec`는 정수 초로 유지한다. 기존 챌린지의 `durationMode: choice`는 세 가지 선택을 제공하고, 고정 `60` 또는 `180` 챌린지는 관리자가 정한 고정 모드만 제공한다. 자유 양치를 관리자가 단독 지정하는 기능은 이번 범위에 포함하지 않는다.

## 8. 실패와 정리

- 진행률 조회 실패: 스킨 단계에서 재시도하며 권한 요청 전이므로 카메라는 열지 않는다.
- 카메라 권한 거부: 기존 타이머 전용 화면으로 이어 간다.
- WASM 또는 모델 로딩 실패: 카메라 영상은 유지하고 AR만 끈 뒤 “AR 효과 없이 계속 진행해요.”를 표시한다.
- 추론 중 예외: 추적 루프를 한 번 종료하고 같은 대체 상태로 전환한다.
- 얼굴 미감지: 타이머를 유지하고 얼굴 안내만 표시한다.
- 완료, 화면 이탈, 컴포넌트 해제: animation frame, 추적기, video 참조, 모든 미디어 트랙을 정리한다.

AR 실패는 제출 실패가 아니다. 카메라는 켜졌지만 AR이 실패한 경우 `cameraMode`는 계속 `camera`이고 `faceDetectedSec`만 `null`이다.

## 9. 개인정보와 네트워크

Face Landmarker 추론은 학생 기기에서만 실행한다. 개발·운영 로그에 랜드마크, 얼굴 감지 결과의 프레임별 값, 영상 URL을 남기지 않는다. 정적 WASM·모델·스킨 파일 요청 외에 카메라 프레임으로 발생하는 네트워크 요청은 없어야 한다.

서버로 보내는 새 값은 기존 완료 계약의 `faceDetectedSec`뿐이다. 어떤 스킨을 골랐는지는 이번 단계에서 서버에 저장하지 않는다. 향후 컬렉션 기능이 추가되면 별도의 보유·착용 스킨 계약을 설계한다.

## 10. 테스트 전략

- 순수 단위 테스트: 마지막 날 왕관 규칙, 좌우 반전 좌표, 크기·회전 계산, 보간, 감지시간 상한, 자유 양치의 60초/300초 경계
- 컴포넌트 테스트: 기본 스킨 세 개 선택, 마지막 날 선택 생략, 60/180 감소 타이머, 자유 양치 증가 타이머, 얼굴 이탈 안내, AR 실패 대체 문구
- 수명주기 테스트: 완료·이탈 시 추적기와 카메라 정리
- 계약 테스트: `faceDetectedSec`가 숫자 또는 `null`만 허용하고 좌표 데이터는 거부
- 브라우저 테스트: 카메라 거부 시 기존 흐름, 가짜 추적기를 이용한 얼굴 감지 흐름, 마지막 날 왕관 흐름
- 수동 실기기 테스트: Android Chrome과 iPhone Safari에서 위치·크기·회전, 프레임율, 발열, 세로 화면 겹침 확인

## 11. 제외 범위

- 양치 정확도 또는 칫솔 위치 판정
- 얼굴을 이용한 학생 식별
- 사진 촬영, 녹화, 공유
- 이번 단계에서의 스킨 수집·잠금·관리자 업로드
- 3D 스킨, 표정 인식, 다중 얼굴 지원
- 완주 이후 왕관을 컬렉션에 영구 저장하는 보상 시스템

왕관의 영구 지급과 컬렉션 저장은 Phase 4에서 서버 권위 보상으로 구현한다. 이번 단계에서는 마지막 도전일의 AR 경험에만 자동 적용한다.
